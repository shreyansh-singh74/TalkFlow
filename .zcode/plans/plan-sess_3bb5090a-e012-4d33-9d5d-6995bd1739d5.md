# Plan: Call flow — connecting gate, completion popup, smooth exit

Three related flow problems, one plan:

- **A. Call UI renders before connecting** — joining shows a half-initialized screen ("Connecting…" as the sentence, phantom audio player, amber "Connecting to voice server…" banner).
- **B. Completing the last step doesn't show the completion/report screen** — the coach's closing line plays, but no "Practice Complete" popup appears.
- **C. Broken exit flow** — after leaving, a dead-end "Practice Session has Ended" screen with no buttons appears (screenshot 2), and the learner has to use browser back instead of landing on their analytics.

Root causes found in code:

- **B:** `handle_end_turn` sends `SESSION_COMPLETE` only **after** the coach's closing TTS fully streams (`voice_websocket.py:816-825` — `stream_tts_batched` is awaited before `_send_report()`). The report is delayed 10-20 s behind the spoken reply; if the learner clicks Leave during that window, the flows race and the popup never shows. (Report generation itself is resilient — `generate_coach_summary` falls back on failure.)
- **C:** When the leave mutation marks the session `completed`, react-query refetches `/api/sessions/[id]`, and `call-view.tsx` reacts to the status change by replacing the end screen with a dead-end `ErrorState` — unmounting `CallEnded` and its CTA. Those `ErrorState` branches also have no buttons at all, so a stale `/call/[id]` link strands the learner.

## Part A — connecting gate (as previously planned)

1. **`use-push-to-talk.ts`**: add `hasTarget` (set on first `PRACTICE_TARGET`; stays true for the session, so no gate on reconnects or "Practice Again") and `retryConnection()` (reset backoff attempts + `connect()`).
2. **New `call-connecting.tsx`**: full-screen connecting state — pulsing ring, "Connecting to your coach…", live status line (reconnecting countdown from `error`; after ~8 s a hint about the backend/microphone), Cancel + Try again buttons, light theme matching lobby/call-ended.
3. **`call-active.tsx`**: render order → `fatalError` screen (unchanged) → `!hasTarget` → `<CallConnecting />` (replaces practice area + controls) → practice UI. Cancel → `beginLeave()` (no confirm; nothing to save). Gate the `beforeunload` handler on `hasTarget`.
4. No `call-ui.tsx`/backend changes; the backend already sends the first `PRACTICE_TARGET` at the end of `handle_session_config`.

## Part B — completion shows immediately

**`backend/app/api/routes/voice_websocket.py` (`handle_end_turn`):** when `practice_update.session_complete`, send the report **before** streaming the closing TTS — the popup appears the moment the final step is passed, and the celebratory line keeps playing in the background (the audio player is independent of the React tree). Reorder:

```
if practice_update?.advanced:
    if session_complete: await self._send_report()   # moved up, before TTS
    ...
if not self.should_stop_tts:
    await self.stream_tts_batched(...)                # closing line still spoken
```

Client needs no change — `SESSION_COMPLETE` handling already renders `CallActiveComplete`.

## Part C — smooth exit to the analytics

1. **`call-view.tsx` — stop the end-screen swap:** track `hasEnteredCall` (set once `CallUI` renders). The `completed`/`cancelled`/`processing` status gates apply **only before entry**; after that, refetches never override the in-call UI. Joining, leaving, and post-leave screens stay mounted.
2. **`call-view.tsx` — no dead ends:** give the completed/cancelled/processing `ErrorState` branches action buttons — "Open session report" (`/sessions/[id]`) and "Back to sessions" (`/sessions`) — so a stale `/call/[id]` URL always has a way out.
3. **`call-active.tsx` — leave lands on the analytics:** in the `sessionReport` persist effect, when `leavePending` (user clicked Leave, report arrived via finalize), navigate straight to `/sessions/[sessionId]` in `onSettled` instead of calling `onLeave()` — the effect already persisted status + report, so the learner lands on their report page. This replaces the current path (re-mark completed → `CallEnded` → refetch → dead end).
4. **`call-ended.tsx`** remains only for zero-report exits (cancel before speaking, or finalize timeout) — soften its copy to "Everything you practised is saved" (it can't promise analysis that may not exist).

### Resulting flows
| Scenario | Flow |
|---|---|
| Join | Lobby → Connecting screen → call UI with real sentence |
| Pass final step | "Practice Complete" report immediately; closing line plays over it |
| Leave mid-session (turns exist) | finalize → report → straight to `/sessions/[id]` analytics |
| Leave before speaking / finalize timeout | `CallEnded` screen → "View session report" |
| Stale `/call/[id]` after completion | Error card **with** "Open session report" / "Back to sessions" buttons |
| Backend down | Connecting screen with countdown, hint, Try again |
